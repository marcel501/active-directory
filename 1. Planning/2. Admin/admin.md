# INTRODUCTION {{{

This project utilises a customised design activity model (purposed for computing projects) to methodologically deploy a working solution. The project will be a sequential process which methodologically progresses the project allowing a logical flow in prerequisites, preparation before and after the accomplishment of the project.




## AIMS

The aim of this document is to provide a central location in terms of project administration and project management. It is a necessary top level overview to describe the systematical approach towards the assignment.

}}}





___

# METHODOLOGY {{{

The project root directory is split into several modules which are linear/structured (correspond to the primary flow of the project). Such modules address a specific part of the project, they are listed sequentially with a number signifying the position which the module is at and allows for tracking the progress.




## STRUCTURE

1. Planning: General top-level project planning.
2. Specification: Specific scope specific planning & definition declarations.
3. Design: Conceptual design of the lab system by constructing logical and physical models using software.
4. Simulation: Software based work involving simulation.
5. Deployment: Hardware based work involving hardware preparation, deployment & testing.
6. Analysis: Discussion & comparison of hardware and software elements. Conclusion.




## VERSION CONTROL

As an extended part of this project, the primary version control for files within this project will be git. This will allow a more automatic and cleaner methodology, allowing members within the project to remain with a clean working directory.
